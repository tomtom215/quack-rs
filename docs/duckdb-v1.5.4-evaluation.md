# DuckDB v1.5.4 / v1.4.5 Compatibility Evaluation for quack-rs

**Date:** 2026-06-28
**DuckDB Releases:** v1.5.4 (Variegata) and v1.4.5 LTS (Andium), both 2026-06-17
**quack-rs Version evaluated:** 0.14.0
**Bindings before:** `libduckdb-sys` / `duckdb` 1.10503.1 (DuckDB 1.5.3)
**Bindings after:** `libduckdb-sys` / `duckdb` 1.10504.0 (DuckDB 1.5.4)

## Executive Summary

DuckDB v1.5.4 and v1.4.5 are **bugfix / performance / security-patch releases**.
The **C Extension API version is unchanged at `v1.2.0`** — verified directly from
`src/include/duckdb_extension.h` at the `v1.5.3` and `v1.5.4` tags. The
`DUCKDB_TYPE` column-type enum is **byte-for-byte identical** between the two
tags (max value `DUCKDB_TYPE_VARIANT = 41`). quack-rs is therefore **fully
source-compatible** with both releases with **zero code changes**; no new
wrappers, `TypeId` variants, or FFI bindings are required.

The only action is a **maintenance refresh**: bump the resolved bindings in
`Cargo.lock` to `1.10504.0` (so `bundled-test` consumers link DuckDB 1.5.4 and
pick up the upstream fixes) and update the compatibility wording in the docs.

## Verification Method (primary sources only)

1. **C API version** — `DUCKDB_EXTENSION_API_VERSION_{MAJOR,MINOR,PATCH}` read
   from `src/include/duckdb_extension.h` at git tags `v1.5.3` and `v1.5.4`. Both
   resolve to `v1.2.0`. The header is autogenerated by
   `scripts/generate_c_api.py`; the `duckdb_ext_api_v1` struct (the stable
   function-pointer table) is frozen for a given API-version string, so an
   unchanged string means no new stable entrypoints.
2. **Type enum** — `enum DUCKDB_TYPE` read from `src/include/duckdb.h` at both
   tags. Identical: ends at `DUCKDB_TYPE_GEOMETRY = 40`, `DUCKDB_TYPE_VARIANT = 41`.
   quack-rs already wraps both behind `duckdb-1-5-3`.
3. **Binding ↔ release mapping** — `libduckdb-sys 1.10504.0`'s build script
   downloads `.../duckdb/releases/download/v1.5.4/libduckdb-<platform>.zip`,
   confirming `1.10504.0` ⇒ DuckDB v1.5.4. Published to crates.io 2026-06-17,
   the DuckDB 1.5.4 release date.
4. **Advisory check** — no CVE/GHSA/RustSec advisory found against DuckDB ≤1.5.3;
   the "security patches" in the announcements are internal hardening
   (out-of-bounds reads, race conditions), not a tracked advisory.
5. **Build verification** — `cargo check --features duckdb-1-5-3` and
   `cargo test --features duckdb-1-5-3` (133 tests) both pass against
   `libduckdb-sys 1.10504.0`. The prebuilt-link E2E
   (`bundled-test-prebuilt` + `DUCKDB_DOWNLOAD_LIB=1`) could not run in the CI
   sandbox because it cannot download the DuckDB release zip; this is an
   environment network restriction, not a compatibility issue.

## Notable upstream fixes (transparent to quack-rs)

These benefit users who upgrade their DuckDB runtime; they need no wrapper
changes. See the official announcements for the full lists.

### DuckDB 1.5.4 (Variegata)

- VARIANT cast reading wrong rows under a filter (#23031)
- MERGE INTO binding for `WHEN NOT MATCHED [BY TARGET]` (#23014)
- Case-insensitive column match in `INSERT … SELECT … ON CONFLICT` (#22825)
- Non-deleted row count in `RowGroupReorderer` (#22911)
- VARIANT shredding analysis vs shredded writing discrepancies (#23194, #23234)
- Allocator / jemalloc heap-trim on flush path; Parquet stats-pruning perf

### DuckDB 1.4.5 LTS (Andium)

- Correct overflow detection when decoding integers from storage (#21482)
- Backport `* NOT SIMILAR TO 'pattern'` (#21177)
- Race-condition fixes, `AddEscapes` escape handling, unbounded row-group growth
  for indexed tables, CSV reader buffer-boundary read fix, Secret Manager fixes,
  out-of-bounds security hardening

## Action Items

### Done in this refresh (patch-level, no functional code change)

1. `cargo update -p libduckdb-sys -p duckdb` → `1.10504.0`.
2. Extend compatibility wording in `src/lib.rs`, `Cargo.toml`/`README.md`
   from "through v1.5.3" to "through v1.4.5 / v1.5.4".
3. This evaluation document.

### Monitor for future releases

- A C Extension API version bump (`v1.2.0` → higher) in a future DuckDB release
  **would** require quack-rs changes and a re-release; the `<2` upper bound on
  `libduckdb-sys` prevents silent adoption until then.
- New `DUCKDB_TYPE` enum values beyond `VARIANT` (41) → add `TypeId` variants
  (non-breaking thanks to `#[non_exhaustive]`).

---

## Conclusion

No DuckDB **feature** or **C-API change** in v1.5.4 / v1.4.5 requires a quack-rs
code change — the SDK is already source-compatible. A **patch-level maintenance
release** (refreshed lockfile + docs) is the appropriate response, keeping
`bundled-test` consumers on the latest DuckDB and the compatibility statements
accurate. The C extension function-pointer API remains `v1.2.0`.
