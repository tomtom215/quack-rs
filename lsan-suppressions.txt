# LeakSanitizer suppressions for the `leak-check` CI job.
#
# There are none, on purpose. This file used to hold `leak:libduckdb.so`, with a
# comment saying it covered only DuckDB's process-lifetime allocations. LeakSanitizer
# matches a suppression against EVERY frame of a leak's allocation stack, and every
# allocation DuckDB makes for a handle has a libduckdb.so frame, so that one line
# silenced exactly what this job exists to find: a wrapper whose `Drop` never calls
# `duckdb_destroy_*`. Checked (fifth review of the safety net): a leaked LogicalType
# or Value exits 0 with the suppression ("Suppressions used: libduckdb.so") and 23
# without it, and the whole `--test ffi_roundtrip` suite (404 tests) reports no leak
# at all with no suppression, because DuckDB's one-time allocations are still
# reachable at exit and LeakSanitizer does not report reachable memory.
#
# If a future DuckDB does leak a one-time allocation that is unreachable at exit, add
# a suppression for that function by name (`leak:duckdb::SomeClass::Method`), never
# for the library.
